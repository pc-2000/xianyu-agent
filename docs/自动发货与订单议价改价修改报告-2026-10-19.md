## 1. 新增自动发货页面

侧栏增加“自动发货”，提供：

- 按当前登录用户有权管理的卖家账号选择、查询及同步商品。
- 商品同步沿用账号 Cookie 中的实际闲鱼用户 ID，分页获取在售商品。
- 按“卖家账号＋商品 ID”保存独立交付内容，例如网盘链接、提取码和使用说明。
- 每件商品分别开启或关闭自动交付。
- 配置是否允许自动改价，以及最低成交价。
- 查看最近交付记录；内容已发送但确认失败时，可单独重试确认，不重复发送内容。
- 同步成功后保存当前在售商品快照，保留原有交付配置；同步分页失败不会误报全部成功。

新配置默认关闭，不会为未配置商品发送默认账号密码。测试使用临时数据库和示例链接，没有为真实商品填入测试内容。

页面截图：`docs/screenshots/auto-delivery.png`（测试账号与测试数据）。

## 2. 付款后交付及无需物流确认

处理链：

```text
闲鱼 WS 交易卡片
  → 校验付款事件、接收卖家、买家、商品及会话
  → 持久化订单事件
  → 读取当前账号、当前商品的自动交付配置
  → 按账号、订单号领取发送任务
  → 通过闲鱼 WS 发送配置内容
  → 调用现有 auto_confirm / SecureConfirm 无需物流发货能力
  → 检查 success=true 后标记交付完成
```

付款事件使用平台交易卡片中的 `TRADE_PAID_DONE_SELLER` 标识。普通文字、单纯下单和待付款通知不会交付。

无需物流确认沿用项目已有 `mtop.taobao.idle.logistic.consign.dummy` 调用，不填写快递公司或运单号。平台是否允许某笔订单操作，仍由平台接口决定。

原先写死的账号密码发送代码已移除。旧版文字关键词和“小刀待刀成”卡片不再直接自动交付，避免绕过付款校验。

失败处理：

- 未配置或未启用：不交付、不确认发货。
- 重复付款事件：不会再次发送已处理订单的内容。
- 发送异常或重启时发送结果不确定：标记待人工核实，不盲目重发。
- 确认发货失败：保留内容已发送状态，允许只重试确认。
- 历史固定回复发送记录：迁移为历史记录，保留防重复发送效果。

发送沿用现有 `send_msg`，其完成表示 WS 写入完成，并非新增了买家接收回执协议；不对跨进程崩溃等异常承诺绝对 exactly-once。

## 3. 下单未付款事件交给 Agent

在原先过滤未付款系统通知之前新增交易事件分支，不再依赖订单详情先入库，也不等待慢速页面查询。

推送内容包括订单号、商品、未付款状态、自动改价开关、最低价、账号优惠限制及近期聊天记录，并要求 Agent：

> 用户已经下单但尚未付款。检查当前商品是否存在卖家报价和买家明确同意的小刀记录；在允许范围内调用订单改价工具。没有明确证据、未启用改价或价格不合法时不得修改，只有工具成功后才能告知买家改价成功。

消息沿用当前卖家账号、当前买家会话的路由。未付款事件标注为平台事件，而非伪装成买家文字。

Gateway 未订阅时，未发送的订单事件保存到数据库；订阅恢复时，在有效期内补发。已付款订单不会再补发旧的未付款改价事件。

## 4. 新增工具与 Skill

新增两个工具，原有 9 个工具保留：

| 工具 | 用途 |
| --- | --- |
| `xianyu_get_negotiation_history` | 获取当前订单会话中的真实议价记录及消息 ID |
| `xianyu_change_order_price` | 使用订单号、成交金额及双方证据消息 ID 修改待付款订单 |

新增 Skill：`openclaw-plugin/skills/xianyu-order-negotiation/SKILL.md`。

工具按实际 Agent 会话绑定服务端生成的订单操作凭证。凭证通过请求头传递，不写入模型可见提示词；模型不能通过自由填写账号或买家 ID 切换操作对象。

后端校验包括：

- 订单凭证有效、订单号属于当前事件、订单仍未付款。
- 商品已开启自动改价。
- 金额为正数、最多两位小数，且为降价。
- 同时满足商品最低价、账号最大优惠比例及最大优惠金额。
- 卖家报价、买家确认是本会话真实记录，商品一致、先后顺序正确且在24小时内。
- 报价金额与目标金额一致，买家不是拒绝或提出另一个价格。
- 成功改价或提交结果不确定时禁止重复提交；明确未提交的失败可以重试。

议价采用保守规则：优先提取明确成交报价，允许同时引用原价、被拒绝的价格；支持卖家报价后买家接受，以及买家提出明确金额后卖家答应两种顺序。同价的“拍下后改价”请求可作为证据。复杂附加条件、多种成交价或不完整证据需重新确认，不由系统猜测。

聊天证据从本次升级后的实际消息记录建立。旧 Agent 记忆不能替代后端要求的真实消息 ID。

## 5. 改价执行方式及边界

执行器使用卖家 Cookie 通过 Playwright 打开真实订单页，而不是猜测未确认的改价接口。

1. 获取订单详情结构化数据，确认单件订单处于未付款状态。
2. 读取当前金额，再次校验价格范围。
3. 定位“修改价格”、明确的金额输入框及确认按钮。
4. 提交前再次检查付款事件及议价校验。
5. 提交后重新查询订单金额，只有目标金额得到确认才返回成功。

找不到入口、状态无法识别或无法确认结果时，工具返回失败，不改商品上架价格，也不冒充成功。目前该执行器只支持可识别的单件未付款订单；真实页面定位及真实改价仍待现场订单验证。

## 6. 数据与接口

新增数据库：`data/commerce_automation.db`，保存商品配置、在售快照、订单事件、交付记录、聊天证据、改价记录及未发送订单事件。事务不跨越网络等待，避免重现旧版数据库锁问题。

主要页面接口：

- `GET /api/automation/products?account_id=...`
- `PUT /api/automation/products/{account_id}/{item_id}`
- `POST /api/automation/sync/{account_id}`
- `GET /api/automation/deliveries?account_id=...`
- `POST /api/automation/deliveries/{account_id}/{order_id}/retry-confirm`

页面接口要求登录并核对账号归属。工具接口为 `/api/bridge/negotiation-history` 和 `/api/bridge/change-order-price`，要求有效的会话订单凭证。

同时补充账号所属 asyncio loop 调度，跨 FastAPI 与账号循环调用时，将操作投递回账号原有循环，避免复用 aiohttp/WS 对象时跨循环执行。

数据库升级前备份：`data/backups/2026-10-19-automation/xianyu_data.db`。

## 8. 使用步骤与待完成现场验收

1. 刷新管理页面，服务重启后如登录失效，使用现有管理员账号重新登录。
2. 在账号管理完成闲鱼登录或平台要求的验证，确认账号 WS 恢复。
3. 打开“自动发货”，选择账号，点击“同步账号商品”。
4. 为目标商品填写真实交付内容、启用自动交付并保存。
5. 如需议价改价，再启用该商品自动改价、填写最低价，并检查账号最大优惠比例及金额。
6. 使用一笔明确允许测试的订单：先完成报价及明确同意，再下单未付款，观察 Agent 工具及实际金额。
7. 对测试商品实际付款，核对买家收到正确交付内容、闲鱼订单变为已发货、交付记录为完成。

在真实订单验收前，应将本次交付视为“实现及隔离验证完成，平台现场验收待完成”。

## 9. 真实小刀订单排查追记

排查订单：`5127548294071008148`。只读页面查询时订单状态为“买家拍下了宝贝，还没付款哦”，实际金额为3.00元，协商目标为2.7元。

### 本次失败的直接原因

下单事件和Agent工具调用均已发生；`POST /api/bridge/change-order-price` 返回409，尚未进入页面执行。

已复现并修复两个错误拦截：

1. 卖家同时提到“2.5不行、原价3元、给您¥2.7”，旧规则将其误判为多种成交金额。
2. 买家先说“2.7我拍下可以给我改价格吗”，卖家随后答应，旧规则强制要求买家消息晚于选定的卖家消息。

修复后，对该笔真实聊天记录的两组证据进行只读校验，均通过2.7元校验。商品底价、账号最大优惠比例、订单归属、消息证据和未付款限制未取消。

- 平台真实未付款文案“还没付款哦”已加入状态识别。
- 浏览器配置对齐项目原有订单查询模块。
- 只读打开改价入口后，页面显示“修改价格待上线，扫码去APP查看”，没有可提交的金额输入框。
- 工具新增 `unsupported_web_price_change` 明确错误码，提示转App或使用经过验证的改价接口，不再只返回笼统超时。
- 不会把当前限制误报为买家没谈妥，也不会声称订单已改价。
