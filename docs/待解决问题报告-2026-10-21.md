# 待解决问题报告

- 日期：2026-10-21
- 范围：闲鱼 × OpenClaw 交付通道（付款识别、自动发货、后台订单、Agent 状态、网页改价）
- 样本：商品「绿绿的荷叶」，订单 `3317147400119062784`，账号 `3019255810_1`，买家 `2201940977739`，会话 `67884367260`
- 证据：`logs/xianyu_2026-10-21.log`（19:05–19:13）、`utils/commerce_automation.py`、`utils/order_detail_fetcher.py`

## 结论

路由没有配错：付款后应由 Python 直接发配置内容，不经过 Agent。失败原因是闲鱼付款报文形态变了，识别器仍只认测试里的完整 `TRADE_PAID_DONE_SELLER` 新卡。后台 `unknown` 是另一条网页抓取失败，并把已知状态覆盖掉。

## 修复顺序

1. **P0** 放宽付款识别（补丁 /「已付款」按钮 / 催发货卡 / `CONTENT_MAP_UPDATE`），仍拒绝买家纯文字。
2. **P0** 漏单补偿：对已付未发货订单补跑 deliver + 确认发货。
3. **P1** paid 后刷新 Agent 会话，停止待付款话术。
4. **P1** 虚拟商品抓取不要等收货地址；禁止用 `unknown` 覆盖已知状态；前端显示「未同步」。
5. **P2** Skill 不再承诺自动改价；网页改价等平台能力。

## 问题清单

### P0 真实付款不被 `parse_trade_event` 识别

- **现象**：买家已付 0.03 元，会话出现「等待卖家发货 / 已付款 / 去发货」，自动发货与确认发货都不跑。
- **根因**：只接受整张新卡片：`contentType=26`、`updateKey` 恰好 5 段且末尾为 `TRADE_PAID_DONE_SELLER:26`、`redReminder=等待卖家发货`。补丁、旧卡局部更新、提醒发货卡全部返回 `None`。
- **证据**：
  - 19:05:48 只有红字「等待卖家发货」，无 `updateKey`
  - 19:05:49 仍是 `1_not_pay_seller`，按钮改成「已付款」
  - 19:06:27 `REMIND_DELIVER_SELLER`，规则不认
  - 19:12:58 `TRADE_PAID_DONE_SELLER` 以 `_CONTENT_MAP_UPDATE` 到来，读不到 `body['10']`
- **建议**：把上述平台信号视为已付款；买家文字「我已付款」继续忽略。

### P0 已配置的自动发货 / 确认发货未执行

- **现象**：19:05:18 已写入交付内容和确认发货配置，付款后既没发内容，也没点确认发货。
- **根因**：交付只在认到 `paid` 后走 `store.deliver`。付款卡没解析成功，这条路径没进。
- **证据**：日志只有「待付款订单已交给Agent」，没有「商品自动发货」。
- **依赖**：先修付款识别，再补跑漏单。

### P1 Agent 付款后仍回复待付款

- **现象**：钱已付，Agent 仍按待付款议价话术回复。
- **根因**：19:05:38 待付款卡合法，handoff 一次；之后没有 paid 事件刷新会话。
- **建议**：识别到 paid 后写入会话状态，并给 Agent 系统通知（已付款、Python 正在发货）。

### P1 订单列表显示 unknown、实付金额为空

- **现象**：后台荷叶单徽章为 `unknown`（前端无中文映射），金额只有 ¥。考研资料单仍显示「处理中」。
- **根因**：列表状态来自 Playwright 扒 goofish 订单页。页面未进入详情（标题仍是首页文案），等「收货地址」超时，50 个文本节点匹配不到状态词，写入 `unknown` 并覆盖先前的 `processing`。虚拟商品本来没有收货地址。
- **建议**：虚拟商品不要等收货地址；WS 已出现待发货时优先写 `pending_ship`；禁止用 `unknown` 覆盖已知状态；前端把 `unknown` 显示为「未同步」。

### P2 网页改价接口不可用

- **现象**：议价能走到改价，提交失败。
- **根因**：`xianyu_change_order_price` 走闲鱼网页改价，平台返回「修改价格待上线 / `unsupported_web_price_change`」。
- **建议**：短期 Skill 改为「改价需卖家在 App 确认」；中期评估 App/开放接口，没有就保持人工改价。

## 明确不是问题

- 买家发「已经付款」骗不了发货：旧版文字触发已关闭。
- 待付款卡交给 Agent 是设计如此。
- OpenClaw 账号绑定、Gateway 端口与这次漏发货无关。
- 考研资料单显示「处理中」是因为它还停在待付款，且没被这次失败抓取覆盖。

## 验收

再下一笔虚拟商品小额单：付款后 1 分钟内应发配置内容并确认发货；后台应为「待发货」且有金额；Agent 不得再讲待付款。买家纯文字「已付款」仍不得发货。
